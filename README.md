# Midea → 米家 · ESP32-S3 串口桥

使用 ESP32-S3 在美的空调和米家空调模块之间转换串口协议，提供网页控制、串口调试、HomeKit 和 BLE 控制。

当前源码版本：**2.5.54**。优化开机 Wi-Fi 初始化，抑制未命名 AP 广播；未配网设备 10 秒即开免密应急热点，访问 192.168.4.1 直达配网页面，默认密码留空自动兼容，并保留高级控制后台入口。适配 **SPARKLEIOT ESP32-S3_MINI / XH-S3E_MINI，ESP32-S3R8、16 MB Flash、8 MB OPI PSRAM**。此项目面向本机美的空调实测开发，其他机型的协议支持需结合回包确认。

## 当前功能

| 功能 | 说明 |
| --- | --- |
| 米家基本控制 | 开关机、模式、设温、风速、摆风、ECO、睡眠和屏显 |
| 自定义七档风速 | 网页设置七档对应的美的风速值，保存后立即用于后续控制和回读，重启后保留 |
| 美的原生倒计时 | 网页及米家设置开机/关机倒计时，读取美的 C0 回包确认结果 |
| 辅热、自清洁、提示音开关 | 接入对应美的协议；是否支持及是否成功以设备有效回包为准 |
| HomeKit / BLE | 网页显示配对信息，Android BLE 支持认证、状态读取与控制 |
| 串口调试 | 分别显示美的、米家和解析日志，支持 HEX 透传 |
| IO16 独立 RX | 临时监听原装美的模块发出的数据，独立窗口显示，不混入空调状态 |
| 自定义网络名称 | 网页分别设置中文 DHCP 主机名和英文 .local 地址，保存后重启生效，配置持久保留 |
| 网页与 OTA | 控制、智能接入、设备、串口、设置分页面；全部资源由 ESP32 本地提供，公共样式和脚本支持浏览器缓存，支持应用固件 OTA |
| 运行指标 | CPU、内部 RAM、PSRAM、Flash、复位原因与串口响应指标 |

米家模块支持识别 C20、`.mc*` 系列以及既有 MA2、M4/M6 映射。部分功能仅适用于 C20 规范；详细行为见 [功能与协议说明](docs/feature-sync.md)。

## 接线

| 链路 | ESP32-S3 RX | ESP32-S3 TX | 参数 |
| --- | --- | --- | --- |
| 美的空调 | GPIO17 ← 空调 TX | GPIO16 → 空调 RX | UART2，9600 8N1 |
| 米家模块 | GPIO7 ← 模块 GPIO17 / MCU_TX | GPIO8 → 模块 GPIO16 / MCU_RX | UART1，115200 8N1 |
| 下载与系统日志 | 板载 USB-C | USB CDC | 不占用上述业务串口 |

信号共地，使用 **3.3 V 逻辑**。不要把米家模块 TXD0/RXD0 的启动日志口当作 MCU 业务串口。

GPIO16 仅在发送美的帧时驱动，发送完成后释放为高阻输入。高阻并不能阻止原装 Wi-Fi 模块同时驱动线路；同时保留两个发送端时，应采用隔离或切换电路，避免推挽输出直接并联。

## 网页使用

设备连接同一局域网后，默认访问 `http://midea-s3.local/`；自定义访问地址后使用新地址，也可使用设备 IP。登录密码来自 `firmware/secrets.h`，可在设置页修改。

### 路由器无法连接时配置 Wi-Fi

ESP32 连续 90 秒未连接路由器时，启动临时热点 `Midea-S3-UART-Setup`（默认无密码开放热点，手机直接连接；若在 `secrets.h` 设置密码则需满足 WPA2 8–63 字节要求）。手机连接该热点后，访问 `http://192.168.4.1/`，输入 2.4 GHz Wi-Fi 名称、密码以及当前网页密码，保存后 ESP32 重启并使用新网络。原网络若自行恢复，热点关闭。该入口沿用项目的网络配置存储，HomeKit 配对不由这项操作清除。热点不会自动配置米家模块。

### 自定义主机名和 .local 地址

入口：**设置 → 网络名称**。两个字段独立配置，电脑上并排显示，详细说明默认折叠。

- **主机名**：向路由器报告的 DHCP 名称，支持中文，例如 `主卧空调`。最多 **31 个 UTF-8 字节**，纯中文约 10 个字；保留大小写，不能含控制字符。输入时显示字节用量。
- **访问地址**：例如填写 `midea-bedroom`，重启后通过 `http://midea-bedroom.local/` 访问。支持 **1–31 位英文字母、数字或短横线**，首尾不能为短横线，大小写统一为小写；不填写 `http://` 或 `.local`。同一局域网内请使用不同的访问地址。
- 点击“保存并重启”后将配置写入 NVS，设备约 3 秒后重启。页面显示新地址及 IP 备用入口，约 8 秒后跳转；需要重新登录。
- 从 IP 打开的网页继续跳转到 IP，从 `.local` 打开的网页跳转到新域名。设备状态页显示当前主机名、MAC 地址及动态访问链接。
- 两项默认仍是 `midea-s3`；“默认”先填入该值，再保存生效。无改动时不重启。升级时保留 2.5.41 保存的名称，作为两项初始值，此后可分别修改。
- 路由器可能优先使用自己保存的备注或识别名称，因此 DHCP 主机名不保证立刻成为终端列表显示名称；`.local` 解析需要客户端支持 mDNS。
- 登录保护 API：`GET/POST /api/network/hostname`，POST 使用 JSON，例如 `{"hostname":"主卧空调","mdnsHostname":"midea-bedroom"}`。两项名称使用同一 NVS 记录保存。

### 自定义风速

入口：**设置 → 米家七档风速映射**。

| 米家档位 | 默认美的风速值 | 米家滑条位置 |
| --- | --- | --- |
| 1 | 5 | 5% |
| 2 | 10 | 10% |
| 3 | 30 | 30% |
| 4 | 45 | 45% |
| 5 | 60 | 60% |
| 6 | 80 | 80% |
| 7 | 100 | 100% |
| 自动 | 102 | 101（协议值） |

- 七个自定义值必须是 **1–100 的整数，严格递增**。这里是协议风速值，不是实测转速。
- 写入和回读共用一张表；美的回报按最接近的值显示档位，距离相同取较低档。
- 米家滑条仍按上表位置选择档位，再转换为自定义美的值。
- “恢复默认”会先填入默认值，点击“保存映射”生效。编辑中的内容不会被后台刷新覆盖。
- 保存映射不立即调速；下次调档使用新值。关闭米家睡眠会使用自定义第 3 档，开启睡眠仍使用美的原始风速值 1。
- 美的处于自动运行模式时，单独调风速不会改变美的风速；显式切换手动模式后可调档。

### 倒计时与预约

开机、关机倒计时分别使用美的原生定时槽，范围为 **1–1440 分钟**；设为 0 可取消指定项。发送后等待实际状态匹配，不把请求缓存当作执行成功。

**2.5.40 已移除网页本地预约功能**：不再提供指定日期或每周重复的预约表单、API 和执行器，启动时清理旧网页预约记录。美居的云端预约不属于 ESP32 本地预约，也不会自动同步到网页。

### IO16 独立抓包

入口：**串口调试 → 将 IO16 切换为 RX**。

- 开启后 GPIO16 按 9600 8N1 接收；暂停 ESP32 向美的发送、USB 透传发送和自动查询，GPIO17 继续接收。
- 数据仅进入独立日志窗口，不用于更新美的实际状态；重启默认恢复 TX。
- 关闭后停止独立日志请求和窗口内容更新。
- “清空日志”同时清除 ESP32 中的 IO16 日志缓存；刷新页面不会恢复已清空的旧记录。字节/批次统计不清零。

### 网页响应与刷新

- 智能接入页采用紧凑布局：米家关键状态在电脑上分三列、手机上分两列显示；同步按钮常驻，统计、串口诊断、查询与测试工具默认折叠。扩展模拟开关放在标题旁，详细规则按需展开。
- 所有页面、脚本和样式都保存在 ESP32 固件中，通过局域网访问，**不使用 CDN 或外网资源**。
- 2.5.43 将公共 CSS/JavaScript 拆为带固件版本号的本地资源，浏览器首次读取后可跨页面复用。缓存后，每次切换只下载约 **3.4–7 KB** 的页面 HTML；首次访问或升级固件后仍需获取公共资源。
- 页面 HTML 和实时接口不缓存，空调状态每 **1 秒**读取，设备指标每 2 秒读取，调试日志约每 700 毫秒读取；后台请求仍依次执行，隐藏页面暂停轮询。
- 空调物理状态仍每 **5 秒**通过串口自动查询，网页刷新频率不等于空调回报频率。控制后仍等待实际回包，不用浏览器缓存或请求目标冒充真实状态。
- 实机基线与诊断范围见 [网页性能记录](docs/web-performance.md)。

## 配置与构建

### 依赖

当前本地编译使用：Arduino-ESP32 **3.3.8**、HomeSpan **2.1.8**、NimBLE-Arduino **1.4.3**，以及 ESP32 核心自带的网络、BLE 和 OTA 库。构建脚本面向 Windows PowerShell，使用 Arduino CLI 和临时 SUBST 盘符兼容中文路径。

仓库不附带工具链和库。`-ArduinoEnvironment` 指向现有 Arduino 环境目录，其下需要有 `data/packages/esp32/...` 与 `user/libraries/...`。也可将环境放到本项目的 `build/ArduinoEnv/`。

### 本机配置

```powershell
Copy-Item .\firmware\secrets.example.h .\firmware\secrets.h
```

编辑 `firmware/secrets.h`，填写自己的 Wi-Fi、网页/AP 密码及独立的 HomeKit 配对码和 Setup ID。示例值仅用于说明，请在使用前更换。

`firmware/pairing_qr.h` 为可选的本机配对二维码文件；缺少时固件显示占位信息，可以使用网页显示的配对码手动配对。私有配置和二维码不提交到 Git。

### 编译

在项目根目录执行，并替换为本机的实际路径：

```powershell
.\build_firmware.ps1 `
  -ArduinoCli 'C:\path\arduino-cli.exe' `
  -ArduinoEnvironment 'C:\path\ArduinoEnv'
```

脚本默认只编译。板卡参数为 ESP32-S3、16 MB Flash、OPI PSRAM、USB CDC；成功后生成：

```text
dist/firmware/Midea-Bridge-2.5.47-ESP32-S3-MINI-web-OTA.bin
dist/firmware/Midea-Bridge-2.5.47-ESP32-S3-MINI-full-flash-16MB.bin
```

- **网页更新使用 `web-OTA.bin`**。
- 完整 16 MB 镜像用于串口从偏移 `0x0` 写入，会覆盖设备 Flash 中的设置与配对记录。
- 两个应用槽各 6.25 MiB，SPIFFS 为 3.375 MiB；布局见 [partitions.csv](firmware/partitions.csv)。
- 构建会将本机配置编入固件，生成的镜像和构建缓存默认不提交到仓库。
