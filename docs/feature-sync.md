# ESP32-S3 功能与协议说明

当前主卧源码版本 `2.5.46`。该版本已独立维护，不能假定与经典 ESP32 或其他 S3 项目源码相同。本机 secrets、HomeKit 身份和配对二维码分别保管。屏显状态从 C0 负载 Byte 14（完整 AA 帧索引 `frame[24]`）读取，显示级别 0–6 为开、7 为关。单独设置灯光开关/亮度时直接发独立 `0x41/0x61` toggle 帧，不再先发无关的全状态命令；关闭关屏、自动/中/高开屏，并等待 C0 回包确认。C20 睡眠状态由 ESP32 RAM 虚拟维护：开启映射原始风速码 1，关闭设自定义第 3 档（默认码 30），不读美的睡眠位；风速反馈和直接调速会清除状态，重启后默认关闭。目标湿度 2.14 继续使用独立 RAM 模拟（实测关闭请求值为 0，1–100 为设定值），不控制美的硬件。C20 模式写入 `2.2=6` 按本机米家重复选择当前模式处理：只回复成功并保持所有实际状态，不重发控制帧，不依赖模式缓存。模式 `2/3/4/5` 正常切换；米家手动关机继续通过 `2.1=false`，实际已关机时的模式查询仍返回 6。MCU 版本 0264。

## 状态同步

米家模块状态为 `offline`、`uap`、`unprov`、`updating` 时暂停自动属性上报，继续网络状态查询和下行轮询；恢复 `local` / `cloud` 时重新同步。在线且设备型号已识别时，即使可选 `mcu_version` 握手未完成也允许上报，避免米家 App 保留旧模式；握手最多尝试三次。ESP32 Wi-Fi 采用 HomeSpan 重连机制，2.5.45 增加异步网关探测和连接质量恶化时的重连恢复；固件未主动设置发射功率上限。2.5.40 已完成本地编译，新功能仍需实机验证。

| 功能 | S3 的处理 |
| --- | --- |
| 美的串口控制与透传 | GPIO17 RX / GPIO16 TX，9600 8N1；GPIO16 仅在发送帧期间连接 UART2 TX，发送完成即设为输入；接收按帧长度及校验解码 |
| IO16 独立 RX 调试 | 主卧 2.5.37 在串口页提供 RX 模式开关，使用 UART0 只收 GPIO16，GPIO17 继续接收。开启时阻止向美的和 USB 透传发送，独立 HEX 日志不参与状态解析；关闭恢复 TX，重启默认关闭 |
| 米家串口 | GPIO7 RX / GPIO8 TX，115200 8N1；识别 C20、MA2、M4/M6；命令、应答、通知进入同一串行事务队列 |
| 双向状态确认 | 米家真实控制需由美的新回包确认；不能仅因 UART 发送成功就返回空调已生效 |
| 重试 | 核心状态与扩展通知每份状态最多发送三次（首次加两次重试）；失败状态暂停自动重复，新的变化才开启新预算 |
| 关机风速 | 美的关机回包的风速字段在共用入口被忽略；网页、BLE、HomeKit 和米家均沿用最后开机风速；关机通知省略风速。重新开机的完整控制帧使用保留值，显式风速请求优先 |
| C20 风速滑条 | 主卧 2.5.40 在设置页自定义米家七档对应的美的风速值（1–100 严格递增，NVS 持久保存）；默认 5、10、30、45、60、80、100。回读与写入共用映射，同距离取低档。滑条位置仍为原七档百分比，101 为自动（美的发送 102）；睡眠关闭使用自定义第 3 档 |
| 自动模式 | 真实美的模式保留 1（自动）；以真实室温减设温估算米家显示：>+2°C 制冷、<-3°C 制热，中间保持历史冷/热方向。估算不是压缩机状态或已验证的本机原厂算法 |
| 自动模式下的控制 | 仅开关/调温时保留实际自动模式；明确写米家模式属性时才切换手动模式。无室温/历史或首次温差正好为零时不猜测 |
| 摆风、ECO、睡眠、屏显 | 摆风/ECO/屏显按实际状态映射；C20 睡眠由 ESP32 虚拟维护，不读/写美的睡眠位，开睡眠设原始风速码 `1`，关睡眠设第 3 档码 `30`；C20 左右固定角度仅接受停/全摆。屏显开关映射灯光 6.1，并使用独立 `0x41/0x61` toggle 帧控制 |
| 温度步进 | 0.1°C 请求取最近 0.5°C，限于美的 17–30°C |
| 环境模拟 | 可选开关保存到 NVS；室温优先真实值，缺少时模拟 23°C；环境湿度模拟为 75%。独立测试按钮上报 23°C/75% |
| 目标湿度 | C20 2.14 本地 RAM 模拟，0 表示关闭、1–100 表示目标值；不向美的发送控制 |
| 脱机模式 | 可选、保存到 NVS；在未接空调时用内存状态调试网页、米家与 HomeKit，避免误认为硬件已确认 |
| 提示音开关 | 主卧 2.5.35 将 C20 5.1 映射美的 B0/B1 属性 0x022C，查询真实状态后确认；普通控制和屏显命令的提示音 bit6 跟随最后确认值，始终保留必需 bit1 |
| 美居完整控制帧 | 主卧 2.5.38 按原厂抓包使用 AA 24 / 协议 0 的 0x40 包，补齐扩展字节及消息序号，偏移 29 对齐原厂 0x80（本机具体含义未确认）；按实际长度重算 CRC/累加校验。用于排查已有 bit6 但无声的问题，实际鸣响尚待实机确认 |
| 独立模拟 | 干燥 2.10（布尔值）和机组体检 9.2（私有字符串）独立 RAM 模拟，正常读写成功，不依赖扩展模拟开关或美的回包；不执行真实硬件功能 |
| HomeKit / BLE | 配对码、二维码、清除配对、网页密码修改、Wi-Fi 设置、设备 IP/网址及控制均保留；Android 使用相同 BLE UUID/协议，蓝牙名为 Midea-S3-Bridge-xxxx |
| 网页与 OTA | 控制、智能接入、设备、串口、设置分页面；完整请求才进入同步解析器；TCP 等待期间继续服务串口；上传断线后核对完整 S3 版本号，最多三次上传 |
| 网页预约 | 主卧 2.5.40 移除本地预约表单、API、状态字段及执行器，并清理旧 NVS 记录；美的原生倒计时保留 |
| 智能接入布局 | 主卧 2.5.44 将米家关键状态改为桌面三列、手机两列；诊断统计、查询与测试工具和长说明默认折叠。扩展模拟卡片保留标题、状态与开关，规则和计数折叠显示；原有按钮、属性 ID、接口和刷新逻辑保持原样 |
| 自定义网络名称 | 主卧 2.5.42 将 DHCP 主机名和 HomeSpan mDNS 地址独立设置；主机名支持中文，限 31 个 UTF-8 字节，mDNS 仅允许 1–31 位字母/数字/短横线。两项以单个 NVS 记录保存，3 秒后重启，兼容旧名称。紧凑设置区并排显示，说明折叠；设备页 URL 由 mDNS 名称生成并显示 DHCP 名称与 MAC。路由器可能优先显示自己的备注 |
| 网页刷新 | 主卧 2.5.43 将 CSS/JavaScript 拆分为带版本号的本地资源，支持浏览器私有缓存和 ETag；所有资源仍由 ESP32 提供，不使用 CDN；网页状态每秒读取，设备自动串口查询仍为 5 秒。主卧 2.5.39 请求超时覆盖正文、后台轮询依次执行；关闭 IO16 时停止独立日志请求与内容更新，清空同时清除设备 IO16 缓存并忽略旧响应，日志批量插入且无新增记录时不强制滚动。主日志 latestId 支持重启后自动恢复游标，避免停刷 |
| 运行指标 | CPU、内部 RAM、PSRAM、Flash/OTA 槽容量，复位原因、串口溢出、回复延迟及服务间隔 |

风速历史和自动模式估算历史仅在 RAM；ESP32 重启后需要新回包建立历史。原始串口日志保留空调发来的真实字节，因此关机原始帧仍可能出现自动风速码。

## 仍需遵守的限制

- C20 没有原生自动模式，网页会标注估算；不能把估算值前成美的的真实手动模式写回。
- 主卧 2.5.36 修正 C20 10.3 写入方向：末位 0 写关机定时槽、1 写开机定时槽；读取显示字段独立保留开机 0 / 关机 1。读取来自最新有效 C0 缓存，最多保留 15 秒，不读取请求目标。支持 1–1440 分钟；保留双引号解析修复，标量 `"0"` 清空两项美的倒计时。写入需等美的 C0 回包匹配才向米家返回成功，超时返回 -4004。
- 主卧 2.5.34 新增辅热 `2.9` 真实布尔映射，读写 C0 / 0x40 帧偏移 19 bit3；自清洁 `9.1` 使用字符串 `"1"`/`"0"` 启动/取消美的 B0 属性 0x0039，并用 B1 查询确认。B5 0x0039 能力声明和 B0 设置回显不能确认实际状态；两项功能均不会被扩展模拟覆盖。
- 风速、摆风等协议细节以及编译环境历史问题见本项目 [README](../README.md)；协议按本机实际回包核对。
- S3 与经典板的二进制不通用。网页 OTA 不会更改分区表，首次切换 16 MB 双 OTA 布局要用 S3 完整串口镜像。

## 后续维护

业务规则修改后同时更新两套串口项目。MIoT 桥、profile、扩展属性、状态解码、自动模式估算、HTTP 请求门控与运行指标头文件应保持一致；`verify_feature_sync.py` 会检查这些文件，以及控制/接收/OTA/BLE/设置函数与全部 HTTP 路由。

S3 的 IO、USB CDC、PSRAM 缓存、域名、BLE 名称、HomeKit 身份、分区与库版本保持板级配置。新增头文件要加入 S3 构建脚本复制列表，不能只修改源码却用旧构建副本。S3 OTA 断线核对必须比较完整 `x.y.z-s3` 版本；`secrets.h`、配对二维码和配对身份不从经典板覆盖。

S3 不再使用显示板 SoftwareSerial 监听功能，因此不需要 EspSoftwareSerial / ghostl 依赖；经典板仍按自身工具链配置。

自动模式控制：美的真实模式为自动时，MIoT 温度设定正常下发并等待回包；风速档位（3.2）和百分比（10.1）写入返回 MIoT 结果后，ESP32 再上报自动风速（档位 0 / 百分比 101），不改变美的风速也不发送风速修改。若同一事务明确选择手动模式，风速请求照常执行。冷热估算只用于米家显示。此规则与经典 ESP32 同步。


2.5.19 同步：网页设置提供 BLE 启停开关，默认开启，NVS 持久化并通过重启生效；自动模式风速请求以正常 MIoT 事务结果应答，随后状态上报自动风速（档位 0 / 百分比 101），不会发往美的。

2.5.46 修正重复模式兼容：从送风切制冷仍为 `2.2=2`。重复选择当前模式收到 `2.2=6` 时只应答、不发送控制，已移除旧版依赖模式缓存强制重发整帧的行为。此规则也适用于自动模式、未建立缓存或状态过期的场景；同包真实模式、温度和电源写入仍分别处理。

2.5.21 同步：撤回错误的 6→制冷特例；保留原生睡眠位、跳过重复整帧写入、最多三次确认查询、避免周期查询叠加、MCTL 解析日志、排除模拟亮度重复上报，以及过短 C0 帧校验。源代码和本机模拟测试同步，未构建/刷写 ESP32 固件。

当前网页不提供串口总开关、美的 TX 开关、米家 RX/TX 开关和 GPIO4/5 显示板监听；串口桥固定运行。GPIO16 始终保留 UART2 TX 矩阵映射，按帧只切换输出使能；UART 不重启，发送结束后回到高阻输入。2.5.27 修正了 2.5.26 输出模式配置覆盖 UART 路由的问题。

## 2.5.46 验证

主卧 ESP32-S3 固件编译通过，OTA 应用镜像 1,845,648 字节；最终输入与当前源码一致，镜像头、分区容量、SHA-256、版本与重复模式保护标记检查通过。

如果已有真实控制等待美的回包，继续保留原有 busy 应答，不用重复模式请求覆盖在途目标或提前确认真实控制。

使用实际 MIoT 事务处理代码回归：重复模式命令零控制帧、未读取过模式、不依赖缓存、实际自动/制冷/除湿/制热/送风、正常冷热切换、显式开关机、混合调温与真实模式写入、状态未知/过期、控制待确认、模拟模式及非法参数。辅助加热/自清洁/提示音与倒计时原有传输测试通过。重复命令返回成功表示该无操作请求已接收，不伪造空调状态或真实控制确认；固件仍需刷入后验证本机米家 App 行为。
